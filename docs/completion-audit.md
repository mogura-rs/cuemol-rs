## Browser trajectory boundaries

Four failures were reproduced before their respective fixes:

- A 96-byte XTC 2023 input declared a coordinate length that overflowed when
  padding and the frame header were added. Indexing stayed at the same file
  position. A test tripwire stopped the repeated reads after six attempts so
  the regression itself could not hang or exhaust memory. Both additions now
  report overflow, and signed atom counts and topology mismatches are rejected
  before coordinate decoding.
- Cancelling a 10,000-frame XTC import while its second file read was pending
  still allowed 19 reads. The indexer and its initial coordinate read now share
  the load's abort signal. Cancellation checks before and after each awaited
  read stop subsequent reads; the observed count is now two. A later valid
  import remains usable.
- A failed frame read could overwrite the result of a newer object rename.
  Successful and failed frame completions now use the same revision check.
  The stale error is discarded, while a current malformed frame still reports
  its error and leaves the current coordinates and index unchanged.
- An oversized or unreadable Action file cleared the busy flag of an unrelated
  pending frame. Action import failures now update their message without
  releasing another operation's busy state or stopping trajectory playback.

The new browser regressions cover both WebGL and WebGPU, preserved redo,
normal error reporting, retry after failure, and later valid imports. Evidence
is retained under `.cache/final-sweep/trajectory`. The inputs are generated by
`web/tests/trajectory-loading.spec.js`; no external data is needed.
All 28 focused browser checks pass after rebuilding the WASM module, including
the eight new regressions and existing loader, Action, rendering and Agent
cancellation checks. This result does not close the later full-suite and
distribution requirements.

## Shared trajectory readers

Three bounded regressions reproduced capacity-overflow panics in the public XDR
float, double and compressed-coordinate readers. Count arithmetic and the
available payload are now checked before reserving coordinate storage. The
compressed path also bounds the claimed atoms by the available bitstream, and
mixed-integer decoding uses a stack buffer instead of allocating for each atom.
DCD reads records into a reusable buffer as bytes arrive, without allocating
the size claimed by a truncated record. The eager readers no longer allocate
an identity selection or copy every complete frame when no selection is given.
TRR and NetCDF decode arrays with one type dispatch per array.

`scripts/benchmark-trajectory-readers.py` generates deterministic inputs and
compares two builds of `trajectory_reader_bench`. The following measurements
use 200,000 atoms and 16 frames, three fresh processes per build, alternating
build order, and two parses per process. Times are medians of the second parse;
RSS is the median process peak, including input and retained output. Loading
files and hashing outputs are outside the timed parse. All coordinate-bit and
cell-bit hashes match for full frames and for a reordered selection containing
a duplicate atom, with every other frame skipped.

| Format, full frames | Parse before → after (ms) | Peak RSS before → after (MiB) |
| --- | ---: | ---: |
| DCD | 4.45 → 3.55 | 77.63 → 76.19 |
| XTC | 66.67 → 37.52 | 45.97 → 42.09 |
| XTC 2023 | 66.52 → 36.83 | 45.97 → 42.09 |
| TRR float | 11.09 → 1.32 | 79.13 → 75.28 |
| TRR double | 11.42 → 1.82 | 115.75 → 111.91 |
| AMBER NetCDF | 16.00 → 1.19 | 79.13 → 75.28 |

The first five formats use the unchanged reader implementation at `e9b1af6`
as the baseline. NetCDF was measured separately after those changes, while its
own parser remained unchanged; it does not call the modified DCD/XDR paths.
This avoids attributing an unrelated change to the NetCDF result. Small
selected outputs show RSS variation up to about 0.1 MiB in either direction.
These inputs do not establish a speedup for every trajectory.

Truncated inputs claiming two million atoms, but containing only a small
header and partial record, previously peaked at 16.9–47.5 MiB. The same cases
now peak at 1.59–1.64 MiB and fail in less than 0.01 ms. No out-of-memory
experiment was needed. The shared core and MD suites pass with the reference
fixtures and QIF declarations present. Bulk-reader tests also preserve signed
zero, subnormal and NaN payload bits and the specified double-to-float rounding.
Raw measurements and before/after failure logs are in
`.cache/final-sweep/readers`.

The mixed-format browser check also reproduced a separate cell-metadata bug:
updating coordinates replaced the cell with geometry alone, dropping the space
group. `getExtData('CrystalInfo')` then returned `null`. All four shared update
paths now preserve an existing group and use P1 when no group is set, matching
the default of the reference `CrystalInfo` extension. This covers initial
trajectory loading, direct frames, averaged frames and browser frame delivery.
It does not claim the reference trajectory player updates cell dimensions in
the same way; its coordinate readers retain box data separately. Native tests
cover P1 initialization, preservation of group 19 and averaged/block-selected
playback, including failed reads that leave the previous frame intact.
The browser check now passes on WebGL and WebGPU with four concatenated blocks
(XTC, single/double TRR and NetCDF), checking all positions and cell dimensions
at all 12 frames before and after embedded QSC restoration. The complete shared
core/MD run passes 447 tests; the focused browser run passes ten tests.

## Averaging directly indexed browser files

`set_frame` accepts an optional `averageRadius`. For example,
`{"objId":1,"frame":20,"averageRadius":2}` displays the mean coordinates of
frames 18 through 22. The window is clipped at either end, and the requested
center frame supplies the cell. This override applies only to the request;
it does not change the saved `frame_aver_size` playback setting. An explicit
zero displays the original frame without an arithmetic round trip.

The native command and asynchronous browser command use the same window and
double-precision accumulation. The browser retains one accumulator and one
decoded frame at a time. It handles windows across raw File blocks, restored
QSC blocks and the boundary between both kinds. A failed neighbor, cancellation
or newer scene edit leaves the visible coordinates and frame index unchanged.
Cancellation is checked before and after each file read. Console Stop and
Agent cancellation stop subsequent reads as well.

The CueMol console accepts `set_frame 1, 20, averageRadius=2`. Ordinary frame
commands preserve the existing playback policy of creating no undo entry.
An Agent turn retains its existing single undo entry. Browser File objects do
not expose synchronous `frame_aver_size` script accessors; use this asynchronous
command directly, or save and restore an embedded QSC to use the shared
in-memory trajectory scripting API. Assigning an unknown JavaScript property
does not attach trajectory data or make that property persistent.

For a mixed QSC/File trajectory, synchronous script properties describe only
the stored QSC portion. Use `list_trajectories` and `set_frame` for the combined
frame range. A further regression reproduced an incorrect stored cursor:
averaging stored frame 5 after appending a File displayed the correct positions
but left the script's `frame` at 11. Successful asynchronous frame completion
now records the stored index without reloading coordinates or changing the
averaging setting. Frames in the external File portion leave that stored cursor
within its own valid range. Both backend regressions check coordinates, stored
counts/cursors and the combined frame number.

The shared core, MD and command suites pass 772 tests; the four optional
external-tool/service checks also pass during final validation. Twenty focused
browser cases pass across the full run and four corrected test reruns. The
test corrections select a topology after QSC reload and respect the existing
rule that ordinary playback does not create undo entries. Both backends verify
exact averaged coordinates before/after restoration and across a newly appended
File block. Cancellation after the second read prevents all later reads; tests
also cover a malformed neighboring frame, retry, Console Stop, preserved prior
undo and the Agent's grouped undo. New imports are serialized behind a pending
frame and retain their busy state while their own read is pending.

## Imported surface preparation and storage

Every render snapshot previously parsed the same imported OBJ, PLY or QDF
payload again. A per-application cache now retains decoded geometry for active
sources, with limits of 32 MiB of allocated mesh buffers and 16 entries.
Source identity uses weak references, so the cache does not keep source bytes
alive. Replacing or mutating source storage invalidates the entry. Style,
transform and visibility changes still apply when preparing each snapshot.
Application clones used by Undo and render jobs start with an empty cache;
changing or clearing the active scene releases entries at the next snapshot.
Oversized individual meshes are decoded without being retained in the cache.

Valid OBJ text and its original bytes now share one allocation. Malformed
UTF-8 still retains the original bytes for export and the same lossy text for
parsing. Binary PLY and QDF no longer retain a lossy text copy, including after
QSC restoration, surface generation and geometry edits.

The following results compare the unchanged surface path at `b738a39` with
the final candidate. Each input uses three fresh processes per build,
alternating build order, with eight snapshots after initial preparation.
All vertex positions, normals, colors and triangle-index hashes match.
Times measure CPU mesh preparation, excluding hashing and GPU drawing; RSS is
the whole-process peak and includes allocator retention from repeated work.

| Input | Repeated preparation before → after (ms) | Peak RSS before → after (MiB) |
| --- | ---: | ---: |
| OBJ, 65,536 vertices | 14.14 → 0.91 | 33.67 → 30.00 |
| OBJ, 147,456 vertices | 33.08 → 2.12 | 227.83 → 66.13 |
| QDF, 147,456 vertices | 5.96 → 2.09 | 189.06 → 50.97 |

The QDF retains 7.30 MiB of source bytes and previously held another 11.00 MiB
of unused text. Its initial load falls from 17.17 to 4.67 ms. Initial geometry
preparation remains necessary; for the large OBJ it measures 34.00 versus
32.67 ms. The cache can retain additional decoded geometry for smaller or
infrequently rendered inputs, so these results do not imply lower memory use
for every scene. The limits bound that tradeoff.

Regressions cover geometry replacement, copy-on-write mutation, Undo/Redo,
style changes, QSC save/reload, binary byte preservation, invalid UTF-8 and
cache eviction. All 717 molecule, surface and shared-core tests pass with the
available reference fixtures. Raw measurements and binary/input hashes are
in `.cache/final-sweep/surfaces`; the reusable probe is
`surface_render_bench` with `scripts/benchmark-scene-snapshots.py --workload surfaces`.
